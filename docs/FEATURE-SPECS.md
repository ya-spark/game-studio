### T2 Skills (content model)
- Content repo `skills.yaml` beside `topics.yaml`: for each subject, year and topic an ordered list of skills (id, display name, prerequisites; default prerequisite is the skill before it in the same topic; others may cross topics or years). Original wording; skill ids and names never mention a curriculum.
- The mapping from skill id to a curriculum reference lives only in a private file in the content repo (`docs/`), never in a pack, catalogue, index, app or the website.
- Item field `skill` (optional in the schema for old packs, **required** once a topic has skills); CSV column `skill`. The first pass assigns a skill to every item (agent proposes, owner reviews English). A topic with no skills yet has one implicit skill, so nothing breaks.
- Validator: the skill exists and belongs to the item's topic; prerequisites form a graph with no cycles; every skill has at least one format with at least 6 items (the minimum window) and is playable by at least 2 games (the universal ones count); warns when a skill has only one format.
- `ItemSelector` can filter by `skill`. Topic order review (C5, still open with the owner) is a prerequisite: skills inherit it.
- Done when: every Scout item has a skill, validators green, owner reviewed the Scout skill list.

### T3 Mastery engine (pure Dart, save version 9)
- Per child, per skill: an evidence list of the latest 10 item results (correct or not, weight, day, format, hint used, timed out); states `locked`, `new`, `practising`, `secure`, `mastered`, plus the marker `secureByCheck`.
- Evidence weights: a 2-option `mcq` counts half; a hint counts as wrong; a timeout counts as wrong except in Scout (never penalised); the fun score of a game is never evidence.
- Advance rule (config in `app.config.yaml`, defaults by app): secure needs, over the latest window, accuracy of 75% (Scout, window 8), 80% (Ranger, window 10) or 85% (Champion, window 10) on at least 2 different days, with at least 6 items in the window; mastered needs a pass in a second format and one revision pass at least 3 days later; a mastered skill not revised for several weeks falls back to secure.
- Skip-ahead check: 5 items of the skill (non-guessable where possible: `mcq` with 3 or more options, or other formats), 4 correct to pass; a pass unlocks the rung and marks its prerequisites `secureByCheck` (they still return in revision); a fail only adds a short wait before trying that rung again. First launch may run a few checks across the year as placement.
- Spaced revision: wrong or weak items return after 1, 3 and 7 days in any game (extends C2).
- Migration from save version 8: a topic with passes becomes its first skills `practising` or `secure` by the old rule so no child loses progress; the old `Mastery` enum maps to the new states for the parent report, goals and Study Map until T5 replaces them.
- Tests: window and weighting arithmetic, day rule, decay, skip-ahead pass and fail, migration of a version 8 save.

## W3 Browser-saved progress (web only; spec 22 Nov 2026, 12:37 PM AEDT; built in game-factory `game_core/lib/kit/progress/browser_progress.dart`)
- **Owner rules:** no backend, no sign-in, no cookies, no network. Progress lives only in the browser's local storage; clearing site data deletes it. App games are paused and not touched.
- **What is saved:** (1) per Constellation rung (skill key `subject/year/id`, so per topic and rung): its `SkillProgress` (latest answers, formats answered right, secure/revision/last day, skip-check flags), from which the state and the 0 to 3 stars are recomputed on load, so stars persist and the rules can change without a migration; (2) per game: the best score (integer).
- **Keys (prefix `amc.`, same as `amc.recent` and `amc.theme`):** `amc.progress.v1` = JSON `{"v":1,"skills":{"<skillKey>":{...SkillProgress.toJson...}}}`; `amc.best.<gameId>` = the score as text. On the web the shared-preferences plugin stores them in local storage with its own `flutter.` prefix (no `dart:html`).
- **Versioning:** `v` in the document. Older versions are migrated on load; a newer `v` than the code knows is ignored (treated as empty and not overwritten until the player answers something). A corrupt document, or one bad rung inside it, is dropped without losing the other rungs.
- **When storage is blocked** (private mode, quota, disabled): every read and write is in try/catch. The games play fully; progress is kept in memory for the visit (`BrowserProgress.storageOk` is false so a page may show "progress is not being saved"); nothing throws.
- **Reset:** `clear()` removes only `amc.progress.v1` and `amc.best.*`, not other `amc.` keys.
- **Not in this item:** coins and rung opening (M8), ads, favourites, the web trail page (next), apps. Tests: `game_core/test/kit/browser_progress_test.dart`.

## G-13 Domino chain (spec DRAFT, owner decisions applied)
- **Status:** drafted 22 Nov 2026 (docs only; `docs/queue/G-13-series-builder.md`). Owner decisions are fixed: concept A "Domino chain", cartoon, toys only, drag and tap, 1 or 2 chains per round, keys as Bridge builder. Every number below is a PROPOSAL. Model: U3 Bridge builder and `game-factory/games/bridge_builder/docs/SPEC.md`. Rewrite of `game-factory/games/series_builder`.
- **Name:** Domino chain (title, how to play, catalog and web cards, docs, `MiniGame.title`). Folder, package and id become `domino_chain` in the rewrite (owner rule 2026-11-22; migrate saved scores with `renamedGameIds`, patch the web build with `patch_renamed_games.py`). No Craft/Scout/Ranger/Champion/Mind/Ember/Presto wording in anything a web visitor sees (W8): the game draws no app name; the "hard" flag is not named after Champion (internal enum `SeriesLevel.hard` stays, no text).
- **Idea:** the steps of a `series` item are dominoes lying shuffled in a tray. The child drags them (or taps a domino, then a slot) into a row of numbered slots on a table, then presses Go. The first domino tips and the chain topples along. Right order: it runs to the last domino and a toy flag pops up with stars. Wrong order: the chain stops at the first wrong domino, which wobbles red with a "?" tag and a line "Step 3 was not next"; the row stays, the child swaps dominoes and presses Go again. No penalty, no lost life, no limit on tries.
- **Walk-through:** prompt on a sign ("Put these in order, smallest first") -> tray of shuffled dominoes -> child fills slots 1..N (Go stays disabled until every slot is full) -> Go -> topple (0.35 s per domino) -> flag, or stop-and-show -> Next. After a stop the dominoes before the break stand fallen (green), the broken one and everything after stand upright; "Fix it" is just continuing to edit; Go is again enabled.
- **Levels (by year, `levelForYear` as today; Study never timed):**
  - younger (Foundation to Year 2): 3 to 4 dominoes (cap 4), tap-to-place is the main way (the drag works too), a "Hint" button (up to 2 per chain) lights the next correct slot, wide gaps, no timer.
  - older (Year 3 up): 5 to 7 dominoes (cap 7), 1 hint per chain, gentle timer 8 s per domino for the whole chain (cap 60 s), shown as a clock and thin bar, stopped while paused; at time up the game stops editing and topples what is placed (the round counts as not first try, `timedOut`), then shows the right order. Study mode: no timer, 2 hints, same rounds.
  - hard (internal flag only): 7 dominoes, 5 s per domino, no hints.
  - Source steps: a series has 3 to 7 steps (185 items: 4 steps 116, 5 steps 37, 3 steps 29, 6 steps 2, 7 steps 1), so the caps rarely cut; longer series use a window of consecutive steps as today.
- **Series item to dominoes:** one domino per step, text as authored (1 to 80 characters, all different). Size class by the longest step in the chain: `short` (all steps up to 24) = tall domino, label wraps to 2 lines at 18 sp min; `long` (any step over 24; 63 of 185 items, 139 of 755 steps) = wide domino, row wraps to 2 lines of dominoes and labels show up to 3 lines at 16 sp min, then "..."; the full text is always the screen-reader label, a tooltip (long press on touch, hover on web) and shown in the "selected" caption bar under the row while a domino is held or chosen. No image field exists in series items today (0 of 185), so no images; if a later item has an emoji (counting items) it is just text. Steps may repeat only in old content: equal texts are interchangeable (as today).
- **Topple animation (exact):** Go pressed: 150 ms "ready" nudge of domino 1, then each domino tips over 350 ms with a 120 ms overlap into the next (a click sound only if the host sound is on). Right: after the last domino 400 ms pause, the flag pops (300 ms scale) with stars. Wrong: the chain runs up to the last correct domino, the next domino (the wrong one) wobbles 3 times in 500 ms and stays upright with a red outline and a "?" tag; a spark and a dust puff at the break; the dominoes after it stay still. The message says which step slot broke ("Slot 3 was not the next step. Try swapping it."); it never says the right answer. Total animation under 3 s for 7 dominoes.
  - Reduced motion (host setting or system): no tipping, no wobble, no sparks; Go shows the end state at once: right = all dominoes lie flat, flag shown; wrong = the broken domino highlighted (red outline, "?" tag, text message), earlier ones green, later ones normal. Colour is never the only cue (tag and text).
- **Scoring and `onAnswered`:** one series item per chain; `QuizSession.answer(correct)` is called ONCE per chain when it is finally solved (or on time up): `correct = true` only if the first Go was right (first try), else false (as Bridge builder: not a first pass, nothing lost). Study mode: always true after solving. Partial rule: no partial credit to the session; the game score gives 10 for a first-try chain (older +2 per streak step to 5), 6 for a chain solved on the second try, 3 after that (a chain is always finished eventually). A hint used in a chain keeps the chain "correct only if no hint was used" for the session (a hint makes it false). `onScore` once at the end.
- **Rounds and pool:** `minPool` 1 (was 3). A round (stage) is `min(2, pool)` chains: 2 chains when the open pool has 2 or more series items, 1 chain otherwise. A session is up to 6 chains (3 stages of 2), never more than the pool size, and each chain takes a different item; the item order is the session's own (`QuizSession`); no item repeats within a session; with a pool of 1 the game is a single short chain (content item fixes that). A chain that is the last of a stage ends at the flag with stage stars.
