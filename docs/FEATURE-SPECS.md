### T2 Skills (content model)
- Content repo `skills.yaml` beside `topics.yaml`: for each subject, year and topic an ordered list of skills (id, display name, prerequisites; default prerequisite is the skill before it in the same topic; others may cross topics or years). Original wording; skill ids and names never mention a curriculum.
- The mapping from skill id to a curriculum reference lives only in a private file in the content repo (`docs/`), never in a pack, catalogue, index, app or the website.
- Item field `skill` (optional in the schema for old packs, **required** once a topic has skills); CSV column `skill`. The first pass assigns a skill to every item (agent proposes, owner reviews English). A topic with no skills yet has one implicit skill, so nothing breaks.
- Validator: the skill exists and belongs to the item's topic; prerequisites form a graph with no cycles; every skill has at least one format with at least 6 items (the minimum window) and is playable by at least 2 games (the universal ones count); warns when a skill has only one format.
- `ItemSelector` can filter by `skill`. Topic order review (C5, still open with the owner) is a prerequisite: skills inherit it.
- Done when: every Scout item has a skill, validators green, owner reviewed the Scout skill list.

### T3 Mastery engine (pure Dart, save version 9)
- Per child, per skill: an evidence list of the latest 10 item results (correct or not, weight, day, format, hint used, timed out); states `locked`, `new`, `practising`, `secure`, `mastered`, plus the marker `secureByCheck`.
- Evidence weights: a 2-option `mcq` counts half; a hint counts as wrong; a timeout counts as wrong except in Scout (never penalised); the fun score of a game is never evidence.
- Advance rule (config in `app.config.yaml`, defaults by app): secure needs, over the latest window, accuracy of 75% (Scout, window 8), 80% (Ranger, window 10) or 85% (Champion, window 10) on at least 2 different days, with at least 6 items in the window; mastered needs a pass in a second format and one revision pass at least 3 days later; a mastered skill not revised for several weeks falls back to secure.
- Skip-ahead check: 5 items of the skill (non-guessable where possible: `mcq` with 3 or more options, or other formats), 4 correct to pass; a pass unlocks the rung and marks its prerequisites `secureByCheck` (they still return in revision); a fail only adds a short wait before trying that rung again. First launch may run a few checks across the year as placement.
- Spaced revision: wrong or weak items return after 1, 3 and 7 days in any game (extends C2).
- Migration from save version 8: a topic with passes becomes its first skills `practising` or `secure` by the old rule so no child loses progress; the old `Mastery` enum maps to the new states for the parent report, goals and Study Map until T5 replaces them.
- Tests: window and weighting arithmetic, day rule, decay, skip-ahead pass and fail, migration of a version 8 save.

## W3 Browser-saved progress (web only; spec 22 Nov 2026, 12:37 PM AEDT; built in game-factory `game_core/lib/kit/progress/browser_progress.dart`)
- **Owner rules:** no backend, no sign-in, no cookies, no network. Progress lives only in the browser's local storage; clearing site data deletes it. App games are paused and not touched.
- **What is saved:** (1) per Constellation rung (skill key `subject/year/id`, so per topic and rung): its `SkillProgress` (latest answers, formats answered right, secure/revision/last day, skip-check flags), from which the state and the 0 to 3 stars are recomputed on load, so stars persist and the rules can change without a migration; (2) per game: the best score (integer).
- **Keys (prefix `amc.`, same as `amc.recent` and `amc.theme`):** `amc.progress.v1` = JSON `{"v":1,"skills":{"<skillKey>":{...SkillProgress.toJson...}}}`; `amc.best.<gameId>` = the score as text. On the web the shared-preferences plugin stores them in local storage with its own `flutter.` prefix (no `dart:html`).
- **Versioning:** `v` in the document. Older versions are migrated on load; a newer `v` than the code knows is ignored (treated as empty and not overwritten until the player answers something). A corrupt document, or one bad rung inside it, is dropped without losing the other rungs.
- **When storage is blocked** (private mode, quota, disabled): every read and write is in try/catch. The games play fully; progress is kept in memory for the visit (`BrowserProgress.storageOk` is false so a page may show "progress is not being saved"); nothing throws.
- **Reset:** `clear()` removes only `amc.progress.v1` and `amc.best.*`, not other `amc.` keys.
- **Not in this item:** coins and rung opening (M8), ads, favourites, the web trail page (next), apps. Tests: `game_core/test/kit/browser_progress_test.dart`.
