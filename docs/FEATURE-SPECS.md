- **W2 Landing page redesign (games-web `site/index.html`; owner, 2026-11-21; SPEC WRITTEN, NOT POSTED, no run until the owner says go).** Replaces the W1a landing page (filter bar plus a flat grid of small cards) with a modern, appealing page where a visitor reaches a game in one click. One static file, same data, same deep links.
  - **Audience (owner decision, do not break):** the page does not tell who it is for and never names an age, "kids", "parents", "teachers" or "age bands". It is designed so a 5-year-old and a 16-year-old both find it easy and good-looking, and anyone can come and learn or play. Nothing is personalised by age. Copy is short and neutral ("Play", "Maths", "English", "Pick up where you left off").
  - **Look:** a modern dark-first design (deep navy base, vivid accent colours, rounded shapes, soft depth), with a light theme that follows the system and a manual toggle (the choice is remembered on the device). Not babyish and not corporate. Big art tiles and big tap targets (44 px minimum, 56 px or more for main buttons), an icon next to every label so it works with little reading. Gentle hover and press feedback only; respect `prefers-reduced-motion` (no animation at all then); no flashing, no sound. Contrast 4.5 to 1 for text, never colour alone for a state, visible focus ring, full keyboard use, 200 percent text. Works from 320 px phones to wide desktops.
  - **Layout, top to bottom:**
    1. Header: text wordmark "Active Mind Craft" (placeholder, easy to swap for a logo later), theme toggle, search box.
    2. Hero: one short headline, three large buttons **Play** (scrolls to the Play shelf), **Maths** and **English** (jump to Learn with that subject chosen), and a **Surprise me** button that opens a random game (random Fun game or a random Quick quiz topic).
    3. **Pick up where you left off** (Recent): the last up to 6 cards opened, newest first, large tiles, one click to open. Hidden until there is something. A small "Clear" link. Reopening a card moves it to the front, no duplicates.
    4. **Play** shelf: one big tile per Fun game (12 today: art about 120 to 160 px, title, small "from Mind Ember" line). A wrapping grid on desktop, a horizontal scroll-snap row on phones.
    5. **Learn**: a row of **year chips** (Foundation, Year 1 to Year 12, only years that have content; the years come from the catalog, not hard-coded), a **Maths / English** toggle (plus "Both"), then topic tiles for the chosen year and subject. Default on first visit: no year chosen, so show a friendly "Pick a year" state with the chips large, not 700 tiles. Tiles show title, subject icon, year, item count. Quick quiz is the default game per topic; a "Game" choice (see More filters) switches to a Craft minigame card.
    6. **More filters** (collapsed): Topic and Game selects, Clear. Same behaviour as today's filters.
    7. Footer: one calm line: this device remembers your recent games and settings, nothing is sent anywhere; no account.
  - **Search:** one box, instant, matches game and topic titles, subject, "year 3", "foundation", game names ("snake", "fractions"); results replace the shelves while the box has text, with a clear button and "No games match" empty state. Results capped at about 60 with a "Show more".
  - **State and links:** keep the existing URL parameters (`type`, `year`, `topic`, `game`) working and add `q` and `subject`; a link to the page with those parameters shows the same view. `catalog.json` format and card `link` values are unchanged, so no change to `make_catalog.py` is needed (an optional additive field, for example a one-line `blurb` per Fun game, is allowed only if it is generated from the apps' own text and the page works without it).
  - **Device storage (owner approved the approach 2026-11-21):** `localStorage` only, keys prefixed `amc.` (`amc.recent` as a JSON list of card ids, max 6; `amc.theme`). Every read and write is in try/catch (private mode, blocked storage): the page works fully without storage, it just forgets. No cookies, no network calls, no analytics, no fonts or scripts from other sites. Recents store only card ids that exist in the current catalog; unknown ids are dropped. Favourites are NOT in this item (a possible W3).
  - **Art:** use the existing `site/art/*.svg` icons (served at `_site/art/<art>.svg`). Give each tile a tint chosen from a fixed small palette by game id or subject (Maths and English each get their own colour); no new image files are required, no people in any art. If a bigger illustration is wanted, draw simple original SVG shapes in the same style. Check each icon looks good at 120 to 160 px; fix or redraw any that do not.
  - **Performance:** about 775 cards today and growing: render only what is shown (a year, the Play shelf, up to about 60 search results), lazy-load images, no layout shift (reserve tile sizes), a skeleton while `catalog.json` loads, a clear retry message if it fails. First paint under 1 s on a mid phone on a fast connection; page weight (HTML, CSS, JS, excluding art) under about 100 KB.
  - **Constraints:** one static `site/index.html` with inline CSS and JS, no framework, no build step, no dependencies (as today); text set with `textContent` (no `innerHTML` with catalog data); the page must stay valid with `<noscript>` message. `games-web` is PUBLIC: no secrets, nothing private. Keep `lang="en-AU"`, the page title and the meta description (rewrite the description neutrally, no age words).
  - **Where:** `games-web/site/index.html` only (plus `site/art/` if an icon is fixed). Do not touch the apps, `game-factory`, `overlay/`, the deploy workflow or the VPS. Then move the `games-web` pin in `game-studio` after pushing `games-web` `main`.
  - **Checks (run and report):** `python3 scripts/make_catalog.py` still passes; `scripts/build.sh --site` then `scripts/serve.sh` (or `python3 -m http.server --directory dist`) and open the page at 360, 768 and 1280 px wide, in dark and light, with a keyboard only pass, with `prefers-reduced-motion`, with `localStorage` blocked and with an empty `catalog.json` (no crash). Test: opening a Play tile, a Learn tile and a Surprise me result each reach a working game; Recent fills, reorders, caps at 6 and clears; every existing deep link `?type=learn&year=3&topic=...` still works; Foundation (year 0) is labelled "Foundation"; a search for "snake", "fractions" and "year 3" returns sensible results. Run Lighthouse (or equivalent) and report accessibility and performance scores; accessibility 95 or more.
  - **Acceptance:** from the landing page, any Fun game is one click away, a Learn topic is at most three clicks (year, subject if needed, topic), the page never mentions an audience or age group, recents persist across a reload on the same device, and nothing in it breaks without JavaScript storage.
